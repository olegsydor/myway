## Приймання сценаріїв

- [x] **Export → Import → Export.** PostgreSQL підтвердив збіг вузлів, ребер, двох layouts, позицій і анотацій після переназначення ідентифікаторів. Перевірено повторний імпорт у заповнений workspace, невалідний JSON, автентифікацію, CSRF і відкат імпорту при помилці запису. Цикл експорту й імпорту пройшов і в Chromium.
- [x] **Workspace Restore (Replace).** Preview повертає кількість вузлів, ребер, layouts, позицій та анотацій без зміни workspace. Перевірено підтвердження, відмову для невалідних даних, повторну заміну, порожній експорт і збереження акаунта та сесії. Примусова помилка запису після видалення старих записів відкотила всю транзакцію. Після заміни дані іншого власника збіглися з попереднім експортом.
- [x] **Browser recovery.** Chromium перевірив скасування preview, завантаження резервного JSON перед заміною, появу відновленого графа у двох вкладках, видалення застарілих записів IndexedDB для поточного акаунта і збереження запису іншого акаунта. Окремо перевірено відновлення локальних змін до заміни.
- [x] **Tenant isolation і concurrency.** Пройшли перевірки рівня API та зовнішніх ключів, конкурентних дублікатів і циклів ребер, узгодженості export під час save і серіалізації імпорту, запису та переходів стану акаунта. Під час Replace другий Restore, Export і запис чекали на блокування. Export отримав цілісний workspace, запис до старого ресурсу отримав 404, операція іншого власника пройшла окремо.
- [x] **Account deletion.** Перевірено відкликання сесій і токенів, блокування workspace, скасування з повторною автентифікацією та відновлення доступу. В Chromium друга вкладка втратила доступ після запиту видалення. Backend-тести перевірили відкат purge при помилці FK, одночасний і повторний purge та збереження даних і доступу іншого синтетичного акаунта.
- [x] **Міграції і резервне відновлення PostgreSQL.** Чиста база й оновлення зі Stage 15 дійшли до ревізії Alembic `a20c02f1a901`. Перевірено права доступу до архіву, очищення при невдалому backup, відмову для пошкодженої контрольної суми, збіг відновлених таблиць, обмежень, індексів і послідовностей. Після відновлення пройшли вхід, ізоляція, читання та запис. Стан джерела збережено, тимчасові контейнери прибрано.
- [x] **Ручне приймання власником.** Власник підтвердив працездатність Export, Import і Workspace Restore (Replace).

Усі операції заміни, видалення та резервного відновлення цього прогону виконано лише на синтетичних даних.

## Залишкові production-завдання

- [ ] Застосувати міграції та повторити відновлення у staging на репрезентативному обсязі даних. Зафіксувати час відновлення і допустимий обсяг втрати даних.
- [ ] Налаштувати розклад і моніторинг backup та purge, захищене сховище, доступ і строки зберігання резервних копій. Перевірити виконання за розкладом.
- [ ] Перевірити HTTPS, cookies та SMTP у середовищі розгортання. Браузерний прогін фінального приймання охоплював Chromium в одному профілі. Матриця браузерів і навантажувальна перевірка залишаються відкритими.

Account Settings Cleanup є наступним окремим UI checkpoint.
